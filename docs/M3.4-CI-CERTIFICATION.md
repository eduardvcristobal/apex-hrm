# M3.4 — Automated Regression & CI/CD

## Scope
This branch is based on `main` and deliberately avoids changes to M3.1–M3.3 payroll, timekeeping, privacy and tenancy business logic.

## Required CI checks
- **Maven**: `mvn -B -ntp verify` with Java 17 and a PostgreSQL 16 service.
- **Migration/startup**: boot the built Spring Boot artifact against a fresh PostgreSQL database; Flyway executes pending migrations and Hibernate validates the resulting schema. Health endpoint must report HTTP 200.
- **Frontend**: deterministic `npm ci`, TypeScript check and production Vite build; Vitest tests validate route normalization.
- **Browser**: Playwright Chromium launches the frontend in development mode and verifies the unauthenticated sign-in screen.
- **Security**: `npm audit --audit-level=high --omit=dev` and Gitleaks committed-secret scanning.

## Current limitations / next improvements
- Vitest and Playwright test runners are pinned and installed as no-save CI dependencies to avoid editing the existing frontend lockfile; they should be committed to devDependencies and the regenerated lockfile in a follow-up once Node/npm execution is available.
- The browser smoke test is unauthenticated; it does not certify employee-to-payroll E2E. Add authenticated, PostgreSQL-backed multi-role browser scenarios once M3.1–M3.3 are merged.
- The basic backend startup gate checks successful migration and a healthy API but not a complete migration roll-forward from production snapshots. Keep production migrations reviewed.
- Set the optional GitHub Actions secret `HRM_CI_MFA_ENCRYPTION_KEY` for MFA-related tests. Do not copy actual production keys into GitHub Actions.
- Security jobs may initially fail on existing vulnerable dependencies; investigate and remediate rather than disabling the gate.
- Enforce branch protection on `main`: require the named M3.4 jobs, prevent merging failed checks, and require PR review. Branch protection must be configured by a repository administrator.

## Running locally
From `backend/`: `mvn verify` (supply `DB_URL`, `DB_USER`, and `DB_PASSWORD` for database-dependent tests).
From `frontend/`: `npm ci && npm run build`, then `npm install --no-save --package-lock=false vitest@3.2.4 && npx vitest run --config vitest.config.ts`.
For browser smoke: `npm install --no-save --package-lock=false @playwright/test@1.56.1 && npx playwright install chromium && npx playwright test --config=playwright.config.cjs`.

## Acceptance
Treat M3.4 as **pending** until the full GitHub Actions matrix is green on the draft PR, and then green again after integrating M3.1–M3.3. A green CI suite alone is not production/privacy/clinical acceptance.
